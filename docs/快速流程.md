# 快速流程（命令行）

一份很小的设置文件加两条命令，完成「导出 PCK → 官方转换 → 打开开发者工具」。引擎 JS/WASM、微信转换器、默认接口文件、空间预算都由插件自动决定，开发者不需要写请求 JSON 或记计划摘要。

## 用法

```text
node wxslim.mjs quick init GAME_DIR --output 已存在的输出目录   # 在游戏目录生成 wxslim-export.json
node wxslim.mjs quick plan GAME_DIR                               # 只读检查：列出要做的事和缺项
node wxslim.mjs quick run GAME_DIR --write --open                 # 导出并转换，然后打开开发者工具
node wxslim.mjs quick cancel 运行目录 --write                     # 取消一次正在进行的运行（另开一个终端）
node wxslim.mjs quick runs 输出目录                               # 列出已有运行及状态（只读）
```

可选参数：`--settings FILE`（设置文件不在游戏目录时）、`--editor GODOT_EXE`、`--release 安装版目录`。

编辑器路径按顺序查找：`--editor`、环境变量 `WXSLIM_GODOT_EDITOR`、游戏工程中插件准备时写入的本机记录。安装版目录按顺序查找：`--release`、当前 runtime 的上一级（插件里的 `kit/`）、源码旁的 `release`。

## 设置文件 `wxslim-export.json`

```json
{
  "schema": "wxslim-quick-settings-v1",
  "template": "full",
  "orientation": "portrait",
  "glx": true,
  "output": "D:/wx-out",
  "appidFrom": "D:/已有小游戏/project.config.json"
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| template | 无（必填） | `full`（完整）、`conservative`（保守）或 `2d`（纯 2D）；`custom` 需要重新编译引擎，会被明确拒绝 |
| confirmNo3d | false | 2D 时必填 true：确认游戏没有用到被移除的 3D 功能。写进每次转换的功能声明，并绑定本次 PCK |
| confirmRemovedModules | false | 保守时必填 true：确认游戏没有用到保守配方移除的 7 个模块 |
| pairProof | 旧设置兼容 | 已保存的值可保留。随附模板始终读取安装版内的引擎指纹单。 |
| orientation | portrait | `portrait` 或 `landscape` |
| glx | true | false 时用 WebGL 做电脑对照 |
| output | 无（必填） | 已存在的目录；每次运行在其中新建 `游戏名-日期-时间` 子目录 |
| appidFrom | 空 | 已有小游戏的 `project.config.json`，打开时把转换结果中的占位 AppID 换成它的 AppID；使用 `--open` 时必填，开发者工具不接受占位 AppID |
| gameName | 工程名 | 小游戏名称 |
| locale | zh_CN | 宿主语言，如 `zh_CN`、`en`；电脑预览包只支持 zh_CN（面板选英文时自动不生成预览包） |
| devtoolsPreview | true | GLX 时额外生成同包电脑预览：开发者工具走 WebGL2、真机走 GLX；需要 appidFrom 和主场景 |
| exportBudgetMiB / importCacheBudgetMiB | 128 / 256 | 导出目录上限、导入缓存允许增长量 |
| largePck | false | 转换预算从 120 MiB 提到 144 MiB |
| loginCode | false | 接入临时登录 code 接口（三个模板都可用，可与 scenes 分包同时用：转换和分包组装都按同一函数在分包接口后接上登录适配再核对；游戏需主动请求，不自动登录） |
| subpackages、scenes | none、[] | `scenes` 时把 `scenes` 里的每个 res:// 场景拆成一个分包，见下文 |
| skipPrewarm、appid | false、 | 与面板一致；skipPrewarm 只在保守和 2D 模板可用（安装版引擎在 profiles.json 标 startupPrewarmSkippable），完整模板会被拦下 |

## 每次运行的目录

```text
OUTPUT/游戏名-20261107-091503/
  requests/   导出与转换的配置和请求（与面板表单生成的完全相同）
  pck/        导出任务目录，full.pck 在这里
  wechat/     转换任务目录，converted/minigame/project.config.json 在这里（纯 GLX 包）
  split/      按场景分包时的拆包任务目录，packs/boot.pck 和各分包 PCK
  interfaces/ 按场景分包时生成的接口任务目录，interfaces.js
  final/      按场景分包且不生成预览包时的组包任务目录，converted/minigame/ 含各分包
  devtools/   电脑预览包（GLX 且 devtoolsPreview 时），minigame/ 与 PACKAGE.json；分包时也放进预览包
  RUN-RESULT.json        运行结束时写入的摘要：状态、错误、包号、可打开的 project.config.json
  cancel-requested.json  请求过取消时才有
```

GLX 包在电脑开发者工具中会因为宿主没有 EmscriptenGLX 能力而按设计停止（`WXSLIM_GLX_CAPABILITY_UNAVAILABLE`），不会悄悄退回 WebGL。因此 GLX 时默认再调用 `convert/assemble-devtools-device.mjs`，把同一份转换结果组装成「开发者工具走 WebGL2、真机走 GLX」的预览包，`--open` 打开的就是它。预览包有自己的包号，真机 GLX 仍需按新包号单独验收。不分包的游戏用「只有一个启动包」的资源配置交给该工具，入口为工程主场景。

## 取消

`quick cancel` 和面板的「取消」按钮走同一个实现（`cancelQuickRun`），分两层，都不强杀进程、不回滚：

1. 在运行目录写 `cancel-requested.json`。快速流程在每一步开始执行前检查它，看到就停在步骤之间。
2. 按 `requests/active-task.json` 找到正在执行的共用任务，调用共用任务核心的 `cancel`（写任务目录的 `cancel.json`）。导出等编辑器子进程退出，转换等转换器子进程退出，然后任务收据记为 `CANCELLED`。

运行结果的 `status` 为 `CANCELLED`，命令行退出码为 3。已写入的导出、转换目录保留在本次运行目录，可手动删除。任务还没建立时，取消最多等 15 秒；等不到也会在下一步开始前停下。

## 2D 模板

2D 用安装版的 `engines/pure-2d` 配对（自建 c050，去掉 3D 模块）。安装版读取同目录的 fingerprint.json，核对 JS、WASM 的字节数和 SHA-256。保守版采用同样流程。

导出完成后，快速流程按本次 PCK 生成功能声明：PCK 指纹、2D 功能集和被移除的模块。`removedFeaturesUnused` 只来自设置里的 `confirmNo3d: true`，插件不会替作者判断游戏是否用到 3D，字符串动态加载的资源或类需要作者自己确认。GLX 时同样生成电脑预览包。

## 按场景分包

先往游戏里装分包加载脚本：`quick receiver 游戏目录` 列出要写的文件，加 `--write` 后走共用任务 `resource-project-install`，只新建缺少的 4 个脚本、在 project.godot 插入 `WxResource` 自动加载，不覆盖已有文件，任务记录写在输出目录下的 `*-receiver` 目录。面板的「装分包加载脚本…」调用同一个实现，写完后把自动加载同步到编辑器内存里的项目设置。

导出后快速流程依次运行：

1. 按工程源码算归属（`lib/scene-packs.mjs`）。依赖来自文本资源（.tscn/.tres）里的全部 res:// 和 uid:// 引用。project.godot 的引用、脚本里的路径字面量、没被选中场景用到的其他文本资源，以及它们的依赖都留在首包。每个场景只带走首包和其他选中场景都用不到的文件，脚本和工程元数据始终留在首包。主场景、被首包引用的场景、被别的分包场景包含的场景和被 preload 的场景会被拒绝，错误的 field 为 `scenes`。
2. 共用任务 `resource-pck-partition` 按实际 PCK 字节拆出 boot 和各分包。
3. 写资源配置 `requests/scene-packs.json`：首包入口为主场景，分包根目录为 `scenepacks/包名`。共用任务 `resource-interfaces-prepare` 按它和安装版引擎生成 interfaces.js。
4. 官方转换使用 boot.pck 和这份 interfaces.js。
5. 生成电脑预览包时，同包工具把分包放进预览工程并登记到 game.json；否则共用任务 `resource-runtime-assemble` 把分包写进转换结果的副本（`final/`）。

游戏代码要在进入分包场景前调用 `WxResource.load_pack("包名")`。字符串拼接的动态加载分析不到，需要作者自己确认。

## 只更新游戏资源

```text
node wxslim.mjs quick refresh GAME_DIR --run RUN_DIR --write [--open]
```

面板的「只更新游戏资源」按钮走同一个实现（`quickRefresh`）。只重新导出 PCK（临时目录 `RUN/refresh-日期-时间`，替换完成或取消后删除，出错时保留并写 `REFRESH-RESULT.json`），不再跑微信转换器：

1. 核对 RUN 是一次已完成的运行，且模板、GLX、横竖屏、语言、游戏名、登录 code、大 PCK 和引擎 WASM 都和那次一样，否则提示完整导出；按场景分包的运行要求分包场景也和那次一样。
2. 导出 PCK，保守和 2D 模板先做被裁类检查（见下）。
3. 直接更新那次运行在开发者工具里打开的工程（电脑预览包、组包结果或转换结果），不复制、不新开工程：换掉 `data-package/*.data.bin`，同时改写 `wx-game-kit/config*.json` 的 launch.data、`godot-data/package-info.js`、`package.metadata.json` 和渲染配置里的 PCK 指纹与包号（`refreshedFrom` 记录原包号）。游戏资源有变化时再叫一次开发者工具打开同一个工程，它切到前台并重新编译。
   按场景分包时，先和完整导出一样重新拆包（`split`）、重新生成分包接口（`interfaces`，记录各分包大小和指纹），再把首包放进 data-package，把变了的分包写进 `scenepacks/包名/content.bin`，把新接口写进 `godot-data/local-interfaces.js`；包名和上次不一样时停下，提示完整导出。
4. 每次更新追加到 `RUN/REFRESH-LOG.json`。旧版本留下的 `RUN/live/minigame` 仍被识别为那次运行打开的工程。

## 被裁类检查

保守和 2D 模板在转换前、只更新游戏资源前，都会在 PCK 里查找该模板已经不注册的类：`lib/removed-feature-classes.json` 由 `engine/removed-feature-classes.mjs` 从固定的 c050 源码生成（2D：`_3D_DISABLED`、`PHYSICS_3D_DISABLED`、`NAVIGATION_3D_DISABLED`、`XR_DISABLED` 包住的场景与服务器类，加上被移除模块注册的类；保守：被移除模块注册的类）。读场景和资源（.scn/.res/.tscn/.tres）、三种导出方式的脚本和 project.binary。查到即停（`QUICK_REMOVED_CLASSES_USED`，field 为 template）。运行时用字符串拼出的类名查不到，作者确认仍然必需。

## 跳过默认 3D 预热

Godot 的 GLES3 场景渲染器启动时会编译一次默认 3D 着色器，2D 模板也不例外。引擎补丁 `engine/official-startup-prewarm.patch`（第 5 个后续补丁）把这次编译放在项目设置 `startup/gles3/skip_default_3d_prewarm` 后面，默认 false，不设时行为不变。保守和 2D 随附引擎已用它重建（2026-11-08，任务 4a984a92 和 53c9e607，`offline/bundle-rebuilt-engine.mjs` 换入）；完整模板仍用原引擎，不跳过。

`skipPrewarm: true` 时，导出的 `pck/full.pck` 不动，复制一份到 `RUN/startup/full.pck` 并在其中的 project.binary 写入这条设置（`lib/pck-project-setting.mjs`），之后的拆包、转换都用这份；只更新游戏资源同样写入。游戏工程的 project.godot 不改。只改这个开关时，上次的转换结果仍可直接「只更新游戏资源」。跳过后游戏第一次画 3D 物体时会现编这个着色器，可能卡一下。

## 包体大小

导出并转换和只更新游戏资源成功后，`lib/package-size.mjs` 统计开发者工具打开的那份工程，结果放在返回值和 `RUN-RESULT.json` 的 `packageSize`：按 game.json 的 `subpackages` 根目录把文件归到各分包，其余算主包；project.config.json 里 `packOptions.ignore` 的 folder、file、suffix、prefix 规则排除在外（其他规则类型不解析，只会算多不会算少）。超过主包 4 MB、合计 30 MB 或独立分包 4 MB 时写进 `problems`，面板弹窗提醒，不阻止导出。

## WASM 分包

`quick wasmsplit-collect` / `quick wasmsplit-release` / `quick preview`（面板「生成采集包」「生成正式分包」「预览二维码」），实现在 `lib/quick-wasm-split.mjs` 和 `lib/wasm-split.mjs`，调用随附的微信官方 `wasmsplit-v2-ci` 2.1.5。在运行目录的 `wasmsplit/minigame` 副本上操作（原转换结果、电脑预览包不动），状态写在 `wasmsplit/STATE.json`，官方工具输出在 `wasmsplit/logs`。替官方工具处理四件事：`game.symbols.json`（保守、2D 引擎随附 Emscripten 符号表；完整引擎没有，按函数总数生成占位名），预览包的分流 `game.js`（调用时临时换成真机入口，之后把注入写回 `start-device.js`、同样加到 `start-devtools.js`、恢复分流器），iPhone 采集补丁（采集版不能同步等余包时先异步加载），`config.devtools.json` 的 `launch.code`。有分包副本时 `quick status` 的 `openTarget` 指向它，打开和只更新游戏资源都跟着它。实测记录见 `docs/evidence/WASM_SPLIT_2D_20261108.json`。

## 已有运行

`quick runs` 和面板「高级 → 最近运行」读同一个实现（`listQuickRuns`），只读。状态有四种：完成、已取消、失败、未结束。有 `RUN-RESULT.json` 时以它为准；没有时（较早的运行或进程中断）从导出、转换任务的 `terminal.json`、电脑预览包的 `PACKAGE.json` 和取消标记推断。「未结束」表示没有结束收据，可能仍在运行，也可能进程已中断，可以再请求取消。

面板里完成、已取消、失败的运行可以移到系统回收站，删前确认；插件不会自动删除任何运行。

## 和底层的关系

- 请求由面板同款表单生成器产出，再交给 `lib/task-core.mjs`：先生成共用计划，计划不通过就停止；执行时带上该计划的摘要。
- 编辑器指纹、预设、路径冲突、已有输出、磁盘与预算、引擎配对和转换器指纹的检查都没有改动或跳过。
- 每次运行都用新目录，不覆盖旧输出；任一步失败即停止，不重试、不回滚，已写入的内容保留在该运行目录。
- `quick plan` 会在系统临时目录生成草稿并跑一次共用导出计划，用完删除；游戏工程和输出目录不写入。转换计划依赖导出产物，只在 `quick run` 中进行。
