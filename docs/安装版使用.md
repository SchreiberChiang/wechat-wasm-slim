# Godot 微信 GLX 插件安装版

把整个 release 目录保存在固定位置。它包含 Godot 编辑器插件、Node 任务核心、微信官方转换器 1.0.35 和三套经验证的 JS/WASM。仅将小型编辑器插件装入游戏；大型工具留在 release。需要本机 Node 24.18.0、Godot 4.7.2 和微信开发者工具。

**安装和升级：双击 release 里的「双击安装.cmd」。** 先关闭正在编辑这个游戏的 Godot，在弹窗里选择游戏文件夹（里面有 project.godot）。程序会自动查找 Godot 4.7.2：先看上次用过的，再找 Steam 库和 winget；找不到时让你手动选择 .exe。已经装过插件的游戏会自动升级，旧版插件留有备份。安装完成后插件会自动启用，不用再去项目设置里勾选。

命令行等价写法（在 release 目录运行，路径有空格时保留引号）：

```powershell
node install.mjs "D:/游戏工程" "D:/工具/godot.windows.opt.tools.64.exe" --update
```

用 Godot 打开游戏，右侧出现两个停靠栏：

- 「微信导出」：日常使用。选完整或 2D 模板、填 AppID 和输出目录并保存，点「导出并转换」，完成后点「在开发者工具中打开」。运行中可点「取消」，不回滚；「高级 → 最近运行」可以重新打开以前的输出，或把取消、失败留下的目录移到回收站。目前支持完整和 2D 模板，不分包。2D 要勾选「确认游戏没有用到 3D 功能」，转换时会自动核对安装版内的引擎指纹单。选 GLX 时会另生成电脑预览包：开发者工具走 WebGL2，真机走 GLX。
- 「微信导出·旧版（待并入）」：保守版和自定义模板、分包、自建引擎、按请求文件打开任务等高级操作，可以选择本项目或另一个 Godot 游戏的 Web 预设并导出 PCK。这些功能并入新面板后移除。

安装定位记录在游戏自己的 `.godot/wxslim/` 中。任务状态默认放在本机 LOCALAPPDATA/Godot/WxSlim/projects 的项目专属目录，也可用 --state-root 指定游戏目录之外的位置。删除该缓存或移动发行目录后，重新双击安装即可。安装器核对发行清单及旧安装的字节，更新时保留旧插件备份，并在 project.godot 中启用插件：插件注册的导出过滤负责把面板脚本排除出游戏包。命令行导出时如果插件装了却没启用，会直接提示，不会继续导出。微信开发者工具安装目录须位于启动 Godot 时的 PATH。

| 配对 | 选择 | JS/WASM |
|---|---|---|
| 完整版 | 新版完整 c050（含输入、音频和网络修正） | engines/full/ |
| 保守版 | 自建 c050 配对 | engines/conservative/ |
| 纯 2D | 自建 c050 配对 | engines/pure-2d/ |

各目录中选择 godot.prepared.js 和 godot.wasm；工具选择 tools/wx-transformer-v1.0.35-win.exe。默认三维简单游戏用 runtime/convert/assets/simple-delivery-interface.js。自建配对仍要求原始配对准备配置及与本次 PCK 绑定的使用声明；随附的保守和纯 2D 配对使用各自引擎目录里的 fingerprint.json。源树和编译链可外置。选择 GLX 时实际设备能力不足会显式报错，选 WebGL 可做本地桌面对照。

执行顺序为生成草稿、保存本地选择、只读计划、准备执行和确认。转换输出打开 converted/minigame/project.config.json。首次需要绑定 AppID 时，选择本机有权使用 WXGameKit 的项目配置。游戏 PCK、AppID、测试账号、运行日志和签名材料单独管理。

日常安装与使用用本目录。Claude 修改界面、修复功能或合并补丁都使用单独的 source 项目，回归通过后由维护脚本再生成安装版。
