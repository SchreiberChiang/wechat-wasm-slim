可以放在**一个Godot主场景、八个页面**里。保留“上一项 / 切换阶段 / 下一项”三个按钮，每阶段一直停留；只创建当前项，退出时释放该项内容。不同时堆八套视口、灯光和模型，以免混入额外资源压力和跨项状态。页面名称、阶段、当前实时画面、对应参考图和一两句验收目标分开布局；参考图注明原生环境，不能冒充手机GLX结果。

建议最少19个手动阶段；同一目标的数值梯度可在一阶段并排呈现，减少来回切换。不是重新做31个轮播状态。具体像素相同不是验收要求，以下目标强调可见差异。

## 停止条件与未覆盖

- 实际不是GLX、包/SDK身份不清，先记录环境问题，不能当GLX通过。
- 崩溃、shader链接失败或明显画面异常先保存当前证据并定位，不自动继续所有阶段，不切库/加探针掩盖。
- iOS15已有多灯相关崩溃报告：在问题未查清前不能要求用户反复遍历R08来“刷通过”；该环境相关状态保留未完成。
- 当前列表不覆盖面积灯、顶点光照、shadow-to-opacity、各向异性、背光、所有雾/色调映射/运动向量变体、多相机长期切换、性能压力和真实游戏。涉及这些分支的产品需求另行安排，不能因源码中同步改过函数就写为已验证。
- 允许自定义light改写alpha的特殊语义尚未独立验收；不能为了减少状态把“保留材质alpha”和“强制忽略用户代码的alpha修改”混为一谈。后续若需要此能力，先核实固定Godot语法和生成代码，再提出独立用例。
