旧 helper、三个原始 result/targets、未知会话状态、读取表达式及原包/两份 vConsole 不改不覆盖。新增本地保存索引与前后校验在原工具仓库 `.local/glx-inspector-response-audit-20261025-01/`。私有数据仍不进 Git。

## 新增差异

独立源码位于 [examples/glx-native-inspector](../examples/glx-native-inspector/README.md)。没有修改手机包、WASM、GLX 静态库、公共 adapter、帧提交或安装的 pymobiledevice3。

| 层级 | 新记录 | 分类规则 |
| --- | --- | --- |
| 完整应用列表 | 请求尝试/发送完成/错误、回复次数、序号/时间、最后数量、handler 完成数 | 未收到是 null；收到空字典才是 0；发送未结束或根本未发起另列 |
| 微信应用发现 | 完整列表微信数、异步 connected/updated/disconnected 数、当前/历史出现状态 | 通知不是完整列表回复；未观察到不证明微信未开放调试 |
| 微信页面/JS listing | 每应用请求与回复、空/非空、类型数量、代际/孤立历史摘要 | 部分回复不算全部；完整 listing 替换，不累加旧页面；旧代不当新回复 |
| 接收与停止 | 首包类别、清理前 receiver 状态/异常/连接丢失、截止与清理结果 | 正常结束但 connectionLost 仍是中断；清理主动取消不冒充运行异常 |

协议没有逐请求关联 ID，因此“请求后收到同类回复”只有时间/顺序关联，不证明精确对应；返回目标也不证明是当前小游戏。`AutomationAvailability` 单独记录，不能解释成手机设置或 JS 可检查性。

记录在握手前安装；截止时在任何取消 await 前冻结记录和目标。晚到回复不混入窗口，也不触发新的 listing 查询。新增握手子任务取消/收回，防止外层超时后仍留下原 await 创建的自有任务；这是一项本地生命周期保护，没有据此宣称旧手机曾发生任务泄漏。

发送白名单仍只有三类元数据 selector。上游 automatic-inspection 的隐式控制发送会阻止并记录，未放行 attach/eval/自动检查、启动应用或设置变更。新输出独占创建；旧文件存在即拒绝，不读私有选择符或连接设备来覆盖它。

## 本地结果

最新 `python -X utf8 -B -m unittest discover -s examples/glx-native-inspector -p 'test_*.py' -v`：**41 项通过**。未导入真实设备包、读取现有配对/设备选择符，也没有连接任何手机。测试只使用自建 fake 和自有短命 Python 子进程；补齐损坏回复 selector 与有效列表计数区别后的最终输出为本机 `LOCAL_FAKE_TESTS_05.txt`。

开发过程的失败输出也保留：01 是一项 fixture 未标记发送完成的旧期望；03 是扩展 deadline 后的短 fake 窗口检查失败。随后明确增加“请求截至 deadline 尚未开始”状态，将本地 fake 的观察预算从 20ms 调到 120ms，补齐独立截止合同，真实默认仍为 2 秒。02 的 35 项中间通过不替代最终 41 项结果。

覆盖的关键失败路径包括：应用列表未回/明确空、微信 listing 未回/明确空/有目标、多个微信应用只部分回复、发送未完成、接收异常和正常断开、局部/总操作截止、迟到数据、清理失败/抗取消，以及输出/授权/隐私门禁。外层20秒只结束自有 helper；如果取消不协作，不能保证两项资源都已关闭或结果 JSON 完整。此时只报告硬截止，不能算空列表。

这些结果不证明当前 iPhone 会返回目标，不判断微信是否开放调试，也不补记任何 GLX 生命周期通过项。

## 第04次单独获批的实际枚举

用户明确批准按该方案一次只读枚举；原USB、既有配对与明确设备选择，当前游戏会话仍记未知。执行前核验5份审查快照/工作区文件SHA及15项保留材料；只运行一次自有helper，没有失败重试、连接重试或切传输。

| 层级 | 实测记录 | 结论 |
| --- | --- | --- |
| 连接与配对 | 通过既有配对/指定身份门禁，Inspector初始连接完成 | 已进入元数据阶段 |
| 应用列表请求 | 1次尝试、1次发送完成，无发送错误 | 不是发送悬挂 |
| 完整应用列表回复 | 收到并处理2次，最后一份7个条目，其中1个微信条目 | 已发现微信；条目数不是手机已安装应用或真实进程总数 |
| 微信页面/JS listing请求 | 2次尝试均完成发送；对应库收到两份完整列表后自动查询的路径 | 只有一次helper/显式应用列表请求，没有外部重试 |
| 微信listing回复 | 收到并处理2次，最后一份目标数0，最新回复在最新请求之后 | 本次最后明确回复为空，不是等待超时；协议关联仍限时间/顺序 |
| 超时与接收健康 | 两层replyDeadlineExpired=false、sendIncompleteAtDeadline=false；冻结前receiver运行、connectionLost=false、无异常 | 本次没有观察到回复超时、发送失败或接收中断 |
| 结束 | helper正常退出0、stderr空；Inspector/provider均closed | 已停止，不附加或读取snapshot |

记录只保留回复总次数和**最后数量**，没有单独保留第一次的列表大小，不能补写“两次都为空”或“两次都非空”。首次入站类别为automation-state，上报 `WIRAutomationAvailabilityAvailable`；这不是当前小游戏JS可检查或手机某个设置已开启的证明。没有异步应用连接/更新/断开通知，blockedSendCount和processingErrorTypes均为0。

本次将发现失败的位置收窄为：**已列出微信应用且收到其listing，最后listing没有公开可枚举目标。** 不能由这一窗口推断微信永久未开放调试、game worker不存在/已停止，或特定手机设置有误。没有任何目标可关联当前游戏；JS会话仍未知，也没有原冻结会话数据。

按停止条件，未附加调试器、执行JS、读取snapshot、启动/重开应用、换包、清缓存或改设置。授权只用一次，没有追加探路。原始私有响应与回执保存在本机 `device-enumeration-04/`；脱敏索引为 `ENUMERATION_RESULT_04.json`，本地最新状态为本审计目录的 `CURRENT_STATE.json`，旧审计目录的同名状态未覆盖。
