## 下一步真机方案（未授权，未执行）

1. 先核对手机、微信账号和实际基础库。此前安卓另一个账号不在工具当前下发范围内，不能重按当前账号推送解决；若需切换工具账号或下发版本，单独报操作范围。项目配置版本不能替代实际 Wechat Lib/SDKVersion。
2. 拟用当前 iPhone，只有用户明确批准这个候选及操作次数后才上传一次新预览并换包。旧作者包、自构建正常/失败包、原三角形包继续保留；换回也另确认。无云上传、无自动回退、不清缓存。
3. 首轮按顺序各一次：首次打开、退出小游戏后最近入口重进、上滑结束微信再打开、切后台后返回。前一项实际画面正常且有实际 GLX 证据后才进入下一项；任何黑屏、异常或版本不符立即停留原现场，不反复尝试。
4. 每轮对齐 packageId、sessionTag、设备/微信/实际基础库、scene、请求/实际模式、shader 编号与类型、编译错误、三角形及背景实际表现。新 JS session 不能独立证明新微信进程，强退证据若无 PID 就如实注明来自用户操作确认。vConsole 全量日志及授权后截图只留本地。
5. 主复现范围需要覆盖此前发生故障的 3.17.5；当前或另外 3.15.2 的通过不能替代。不同版本按独立轮次和授权记录，不在这轮电脑准备中擅自切换。
6. 各一次排雷通过后，再申请同一候选累计 10 次普通退出重进、3 次强退重开、3 次后台恢复。类型一致、初始化或 swap 不能替代真实画面；不清楚背景是否持续变化时标未验证，不把失败用重试覆盖。

当前候选只有三角形与原有背景，没有 Godot 音频/输入/3D 场景，这些不属于本层通过范围。只有该层在限定设备、版本与操作上稳定后，才讨论最小 Godot。若本层失败，先分析其对象/类型、宿主和提交链，不启动完整引擎编译。

shader 类型只在创建及首次失败时采样。若退出重进返回原 JS 会话，只出现 show/hide 而没有新的 shader 事件是预期情况，记录为恢复原会话，不冒充一次全新初始化或把缺少新采样当成失败。
