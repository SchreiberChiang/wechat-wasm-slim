## 这次能回答什么

此前失败会话 `dcd3d486` 中，Godot 请求顶点类型 35633，GLX 同步 TYPE 查询经过 JS→WASM 整数转换后为 35632；两路源码完整一致。已排除当前 specialization 随后的片元创建或失败删除发生在这条诊断之前。共享 ID 冲突、平台对象类型及平台实际编译输入仍未证实。完整链路和接口缺口见[生命周期核对](GLX_OBJECT_LIFECYCLE_20261024.md)。

本候选只补一处观测：TYPE 的现有同步 `batchRender` 返回在进入 WASM 之前，究竟是什么 JS 类型和值。精确 arm 紧邻既有 TYPE 查询；观察一次后原值原样返回。只读取 `typeof`、null 比较、有限 primitive number 值，以及已有调用的参数长度和次数；不访问对象属性、不保存原对象、不转字符串、不解析 batch 或读取私有 heap。

相对上一诊断包没有新增 GPU 查询、flush、延时或 context 操作。旧源码/错误长度上限、一次失败限制和异常控制流保持。新行为发生在已出现的首次编译失败之后，因此是定位实验，不能当成修复；没有观察到错误也不能证明黑屏解决。
