# 简单场景开源交付准备 · 2026-11-03

本轮范围是仓库源码、脚本及静态检查。没有执行引擎构建、编辑器导出、开发者工具、上传或手机操作；没有创建工程/源码/SDK副本，也没有改动冻结包、Claude工作区、历史证据及旧门禁。卡顿优化继续暂停。

## 已准备

- `engine/alpha-preserve-lighting/DELIVERY.md`：现成配对引擎与固定源码重建两条流程、权限/获取缺口、后续验收。
- `delivery-recipe.json`、`delivery-windows-link.patch`：固定源码提交、四补丁顺序、原Windows链接适配、完整profile、026e、工具链指纹及现成引擎配对。
- `delivery-simple.gd/.tscn`、`delivery-project.godot`、`delivery-exports.cfg`：只有一个简单主场景及程序生成资源，普通 MIX 显示带灯光/阴影/48%红片的离屏方块。无验收分页、参考图或旧场景依赖。尚未经过编辑器语法/导出或视觉验证。
- `delivery-loader-edits.json`、`delivery-entry.js`、`delivery-observer.js`：从精确作者归档生成宿主，不读取冻结工程作为默认输入；保留GLX接线及模式拒绝，去掉自动轮播/云转发/历史计时桥，错误警告不被过滤。
- `delivery.mjs`：配方/依赖检查、有限场景生成、PCK资源及字节核验、配套审计、只对原始JS实施一次return 0，默认内存dry run，拒绝覆盖已有输出目录。
- `delivery-build.mjs`：新重建入口，默认只打印计划，显式`--execute`才创建一个checkout并执行。尚未运行过新编排；没有借用旧构建退出码宣称它已通过。
- `delivery-input.example.json`：全占位符私有配置模板，无AppID、凭据或本机路径。
- `delivery.test.mjs`：静态/内存测试。仓库README及引擎README增加新入口，旧记录继续按日期保留。
- `.gitattributes`：新交付源码和规则固定LF，避免新的Windows checkout改变补丁/PCK输入哈希；已只读检查Git规范化前后字节一致。

## 宿主和旧包的边界

新loader保留旧成功包的GLX延迟建上下文与loader终止保护，去掉两处旧计时调用。SDK恢复作者原始调用参数，去掉仅供旧自动演示的启动参数桥。简单场景使用新的身份接口，PCK必须重新导出，不能把旧验收PCK改名塞入。

成功引擎原有shader诊断代码及其输出仍保留；本轮没有为精简示例另编或删除它。默认示例不注入额外的状态查询、像素读回、云日志或shader现场重建。
